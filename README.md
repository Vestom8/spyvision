# Сканер ошибок конфигурации и базовых уязвимостей веб-приложений

Консольная утилита на Python: обходит указанный сайт в пределах одного домена
(до 40 страниц, не более 200 HTTP-запросов), проверяет настройки безопасности
(HTTP-заголовки, HTTPS/TLS, cookies, CORS, открытые служебные файлы,
разрешённые HTTP-методы, опасные места в клиентском JavaScript), выполняет
безопасные активные проверки (отражённый XSS, признаки инъекций в SQL и NoSQL,
инъекция в шаблон, чтение файлов сервера, выполнение команд ОС, разделение
заголовков, открытый редирект, небезопасные формы, утечки технической
информации) и формирует интерактивный HTML-отчёт с диаграммой статистики,
доказательствами и рекомендациями. Для каждой находки в
отчёте указаны тип угрозы (утечка данных, кража сессии, перехват трафика и
т. д.), объяснение опасности простым языком и логика, по которой сканер сделал
вывод.

Сканер **не выполняет деструктивных действий**, не эксплуатирует найденные
уязвимости, не передаёт данные вовне и не сохраняет пароли и секреты
(значения cookie и найденные ключи в отчёте маскируются).

> ⚠️ Запускайте сканер только против систем, которыми владеете вы, или на
> тестирование которых у вас есть письменное разрешение. Сканирование чужих
> сайтов без разрешения может нарушать закон.

---

## 1. Требования

* Python **3.8** или новее (проверено на 3.8–3.14);
* ОС: Windows, Linux, macOS;
* доступ по сети к сканируемому адресу;
* зависимости: `requests`, `beautifulsoup4` (остальное — стандартная библиотека:
  `ssl`, `socket`, `urllib.parse`, `http.cookies`, `argparse`, `re`, `difflib`).

## 2. Установка

```bash
# 1. Перейти в каталог проекта
cd путь/к/проекту

# 2. (рекомендуется) создать виртуальное окружение
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# 3. Установить зависимости
python -m pip install -r requirements.txt
```

Проверка установки:

```bash
python scan.py --help
```

## 3. Запуск

Есть два равноправных способа указать адрес.

**Способ 1: адрес аргументом командной строки**

```bash
python scan.py https://example.com --max-pages 20 --max-depth 2 --output report.html
```

**Способ 2: ввод адреса в консоли**

Запустите сканер без аргумента `URL` — он спросит адрес:

```
> python scan.py
Введите адрес для сканирования (можно вставить полный URL со схемой, путём и параметрами).
Примеры: https://example.com/catalog?page=2&sort=new | 127.0.0.1:8099 | example.com
URL: https://example.com/catalog?page=2&sort=new
========================================================================
Цель: https://example.com/catalog?page=2&sort=new
...
```

Этот режим удобнее для длинных адресов: можно вставить полный URL целиком,
вместе со схемой, путём, параметрами и символом `&` (в PowerShell такой адрес
в командной строке пришлось бы брать в кавычки). Ввод устойчив к кавычкам,
пробелам и угловым скобкам вокруг адреса. Остальные параметры при этом
задаются флагами, как обычно:

```bash
python scan.py --max-pages 10 --output otchet.html   # адрес спросит в консоли
```

Пустая строка приводит к повторному запросу, `Ctrl+C` отменяет сканирование.
Режим работает и при передаче адреса через конвейер:
`echo https://example.com | python scan.py`.

**Схема адреса.** Если схема не указана (введено `example.com` или
`127.0.0.1:8099`), сканер сам проверяет, отвечает ли хост по TLS, и выбирает
`https://`, иначе `http://`. Проверка выполняется на уровне TCP/TLS и не
расходует лимит HTTP-запросов. Выбранная схема печатается в консоль.

| Аргумент          | По умолчанию  | Описание |
|-------------------|---------------|----------|
| `URL`             | спросит в консоли | адрес целевого веб-приложения |
| `--max-pages`     | `40`          | максимальное число страниц обхода в пределах домена (жёсткий максимум 40) |
| `--max-depth`     | `2`           | максимальная глубина обхода ссылок |
| `--output`        | `report.html` | путь к файлу отчёта |
| `--max-requests`  | `200`         | общий лимит HTTP-запросов (жёсткий максимум 200) |
| `--timeout`       | `5.0`         | таймаут запроса, секунды (жёсткий максимум 5) |
| `--delay`         | `0.5`         | пауза между запросами, секунды (минимум 0.5) |
| `--no-active`     | выключено     | только проверки конфигурации, без активных тестов |
| `--no-post-forms` | выключено     | не отправлять тестовые значения в POST-формы |
| `--insecure`      | выключено     | продолжать работу при недоверенном сертификате |
| `--verbose`, `-v` | выключено     | печатать каждый выполняемый запрос |

### Примеры

```bash
# Ввод адреса в консоли (без аргументов)
python scan.py

# Базовое сканирование
python scan.py https://example.com

# Быстрая проверка одной страницы с отчётом в отдельный файл
python scan.py https://example.com --max-pages 1 --max-depth 0 --output otchet.html

# Только конфигурация, без активных тестов (самый «тихий» режим)
python scan.py https://example.com --no-active

# Локальный стенд с подробным логом запросов
python scan.py http://127.0.0.1:8000 --max-pages 10 --verbose

# Сайт с самоподписанным сертификатом (тестовый контур)
python scan.py https://test.local --insecure

# Длинный адрес с параметрами: удобнее ввести в консоли, чем экранировать &
python scan.py --max-pages 5
```

После завершения сканер печатает сводку в консоль и сохраняет HTML-отчёт.
Отчёт — самодостаточный файл, его можно открыть в любом браузере и переслать.

## 4. Что проверяется

### Проверки конфигурации

| Группа | Что проверяется |
|--------|-----------------|
| Защитные заголовки | наличие и корректность `Content-Security-Policy`, `Strict-Transport-Security`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`; устаревший `X-XSS-Protection`; открытый доступ сторонним сайтам (`Access-Control-Allow-Origin` в ответе страницы); небезопасные директивы CSP (`unsafe-inline`, `unsafe-eval`); малый `max-age` у HSTS; дублирующиеся и противоречащие копии заголовков |
| HTTPS и TLS | использование HTTPS; редирект с HTTP на HTTPS (и его тип: 301 или временный); валидность сертификата, срок действия, совпадение домена; устаревшие версии протокола; загрузка HTTP-ресурсов на HTTPS-странице (смешанный контент, активный и пассивный) |
| Cookies | флаги `Secure`, `HttpOnly`; атрибут `SameSite` (допустимые `Strict`, `Lax`; `None` — предупреждение); срок жизни более 30 дней |
| CORS | запросы с `Origin: <сторонний домен>`, `Origin: null`, `Origin: *`; отражение произвольного `Origin`; опасная комбинация `Access-Control-Allow-Origin: *` + `Access-Control-Allow-Credentials: true`; preflight-запрос `OPTIONS` |
| Открытые служебные ресурсы | 27 типовых путей: `/.env`, `/.git/config`, `/.git/HEAD`, `/backup.zip`, `/backup.tar.gz`, `/dump.sql`, `/debug`, `/swagger.json`, `/openapi.json`, `/.svn/entries`, `/.DS_Store`, `/phpinfo.php`, `/server-status`, `/actuator/health`, `/web.config`, `/.htpasswd`, `/docker-compose.yml`, `/config.php.bak`, `/wp-config.php.bak`, `/.aws/credentials`, `/id_rsa`, `/.npmrc`, `/composer.json`, `/package.json`, `/phpmyadmin/`, `/adminer.php`, `/storage/logs/laravel.log`. Читаются только статус и первые 512 байт; «мягкие 404» отсеиваются по эталонному ответу на несуществующий путь |
| HTTP-методы | отправляется `OPTIONS`, анализируются `Allow` и `Access-Control-Allow-Methods` на наличие `TRACE`, `TRACK`, `PUT`, `DELETE`, `CONNECT`, `PATCH`. Сами опасные методы **не вызываются**. Если сервер не сообщает список методов, запись попадает в отчёт с уровнем «Безопасно» — это не уязвимость |
| Листинг каталогов и `robots.txt` | признаки включённого автоиндекса в полученных страницах; служебные разделы, перечисленные в `robots.txt` |
| Клиентская часть страницы | сторонние скрипты и стили без контроля целостности (`integrity`); ссылки `target="_blank"` без `rel="noopener"`; устаревшие библиотеки (jQuery, jQuery UI, Bootstrap, Lodash, Moment.js, Handlebars, AngularJS); кэширование страниц с приватными данными; токены и пароли в адресах; сторонние `iframe` без `sandbox`; адреса почты в коде; формы загрузки файлов; обработчики событий прямо в разметке |
| Опасные места в JavaScript | DOM XSS (данные из `location`, `document.referrer`, `window.name` попадают в `innerHTML`, `document.write`, `eval`); приём `postMessage` без проверки `event.origin`; хранение токенов в `localStorage`; подключение `ws://` со страницы HTTPS |

### Базовые проверки уязвимостей (активные, безопасные)

| Проверка | Как выполняется |
|----------|-----------------|
| Отражённый XSS | в каждый URL-параметр и поле формы подставляется маркер `BAUMAN_TEST_92841"'><x-BAUMAN_TEST_92841>`. Если строка вернулась без HTML-экранирования — фиксируется «подозрение на XSS» с указанием контекста (текст, атрибут, `<script>`). Отражение внутри `<script>` выделяется отдельной находкой с высоким уровнем. Полезная нагрузка не содержит обработчиков событий, поэтому код не исполняется даже при открытии ответа в браузере |
| SQL-инъекция | подставляются значения `'`, `"`, `\`; ответ сравнивается с обычным по статусу, по сообщениям СУБД (MySQL, PostgreSQL, SQLite, Oracle, MS SQL, ORM) и по структуре HTML. Фиксируется «подозрение», эксплуатация не выполняется |
| Инъекция в NoSQL | тот же спецсимвол; в ответе ищутся сообщения драйверов MongoDB, Elasticsearch и Redis, которых не было в обычном ответе |
| Инъекция в шаблон (SSTI) | отправляется выражение `7*191` в синтаксисе популярных шаблонизаторов; находка фиксируется, только если сервер вернул рядом с меткой вычисленный результат |
| Чтение файлов сервера | путь с переходами `..` к заведомо безвредному системному файлу (`/etc/passwd`, `windows\win.ini`); файл только читается, ничего не изменяется |
| Выполнение команд ОС | после разделителя `;` отправляется имя заведомо несуществующей команды; признак — сообщение командной оболочки в ответе. Никакая реальная команда не выполняется |
| Разделение заголовков (CRLF) | значение с закодированными `%0d%0a` и пробным заголовком; признак — этот заголовок в ответе сервера |
| Открытый редирект | параметры с именами `url`, `redirect`, `next`, `return`, `continue`, `target`, `goto` и т. п. заменяются на `https://evil.com`; проверяется заголовок `Location` (и `meta refresh`) **без перехода** по адресу |
| Небезопасные формы | отправка по HTTP; поле пароля на HTTP-странице; метод GET для чувствительных данных; отсутствие поля с CSRF-токеном; отправка данных на внешний домен |
| Утечка технической информации | версии сервера и фреймворка в заголовках и `<meta name="generator">`, абсолютные пути файловой системы, внутренние IP-адреса, комментарии разработчиков, ссылки на `.map`-файлы, трассировки стека и отладочные сообщения, похожие на секреты строки (значение маскируется) |

## 5. Как читать отчёт

Отчёт состоит из четырёх частей:

1. **Шапка с диаграммой** — слева кольцевая диаграмма «Статистика уязвимостей» с
   легендой и общим числом находок в центре. **Уровни кликабельны:** нажатие на
   сектор или на строку легенды («Высокая», «Средняя», «Низкая», «Безопасно»)
   оставляет в таблице «Найденные проблемы» только записи этого уровня и
   прокручивает страницу к ней. Справа — заголовок отчёта, цель, время и блок
   «Общая статистика» из трёх групп: «Что просканировано» (страницы и лимит,
   формы, параметры в адресах, внешние ссылки, глубина, протокол), «Что найдено»
   (всего записей, требуют внимания, уязвимости и проблемы конфигурации,
   подтверждено и требует ручной проверки) и «Как выполнялось сканирование»
   (запросы и лимит с индикатором, проверки, активные тесты и точки ввода,
   запросы без ответа, длительность).
2. **«Как читать отчёт»** — расшифровка уровней критичности и степени
   уверенности; карточки уровней тоже кликабельны и фильтруют таблицу.
3. **Таблица найденных проблем** — колонки «Уровень опасности», «Что нашли»,
   «Тип угрозы» (утечка данных, кража сессии, перехват трафика, внедрение кода
   и т. д.), «Категория», «Где нашли (адрес)», «Насколько точно». Над таблицей —
   фильтры по уровню и по категории (двумя строками) со счётчиками, поиск по
   тексту, кнопка «Сбросить» и одна кнопка «Развернуть все», которая после
   раскрытия превращается в «Свернуть все». Все адреса кликабельны и
   открываются в новой вкладке. Строка раскрывается щелчком по ней (или по
   слову «подробнее») и показывает пять блоков:
   * **Чем это опасно** — что сможет сделать злоумышленник, простым языком;
   * **Почему сканер так решил** — что было отправлено, что найдено в ответе, по
     какому правилу сделан вывод и когда возможно ложное срабатывание;
   * **Что отправил сканер** — запрос с безопасными тестовыми значениями;
   * **Что ответил сервер** — фрагмент ответа как доказательство находки;
   * **Как исправить** — рекомендация.
4. **Приложения** — список просканированных страниц (адрес, ответ сервера с
   расшифровкой, глубина, тип содержимого, количество символов в коде),
   запросы, оставшиеся без ответа, и перечень выполненных групп проверок.

Тексты «Чем это опасно» и «Почему сканер так решил» берутся из базы знаний
`webscan/knowledge.py`: у каждого вида находки там записаны тип угрозы,
объяснение опасности и логика проверки. Чтобы добавить или уточнить пояснение,
достаточно отредактировать соответствующую запись — код проверок менять не нужно.

Уровни критичности:

| Уровень | Значение | Что делать |
|---------|----------|------------|
| **High** | прямая угроза: утечка секретов, доступный `.env`/`.git`, подозрение на XSS, SQL-инъекцию, выполнение команд, чтение файлов сервера, форма с паролем по HTTP | разбирать в первую очередь |
| **Medium** | ослабляет защиту или требует проверки: нет CSP/HSTS/`X-Frame-Options`, раскрытие серверного ПО в заголовках `Server`/`X-Powered-By`, открытый редирект, опасные методы, DOM XSS, cookie сессии без флагов | планировать исправление |
| **Low** | гигиена конфигурации: отсутствие `X-Content-Type-Options`, долгий срок жизни cookie, `.map`-файлы, обработчики событий в разметке | исправлять по возможности |
| **Info** (в диаграмме — «Безопасно») | проблемы нет, запись справочная: валидный сертификат, сервер не сообщает список разрешённых методов, экранированное отражение ввода | к сведению |

Категории: **Конфигурация** — настройки сервера и приложения;
**Уязвимость** — признаки ошибок обработки пользовательского ввода.

Степень уверенности:

* **подтверждено** — факт зафиксирован непосредственно в ответе (например,
  заголовок отсутствует, файл отдаётся со статусом 200 и ожидаемым содержимым);
* **подозрение** — признак требует ручной проверки (например, тестовая строка
  вернулась без экранирования: нужно убедиться, что вывод действительно попадает
  в исполняемый контекст).

Раздел «Замечания по выполнению» в отчёте предупреждает, если сканирование было
неполным: достигнут лимит страниц или запросов, часть форм не тестировалась,
ответ обрезан по лимиту 1 МБ, сертификат не прошёл проверку.

**Важно:** пустой отчёт не доказывает отсутствие уязвимостей. Сканер выполняет
ограниченный набор безопасных проверок и не заменяет ручной анализ.

## 6. Ограничения выполнения (встроены жёстко)

* таймаут запроса — не более **5 секунд**;
* общее число HTTP-запросов — не более **200** (промежуточные редиректы тоже
  учитываются);
* обход сайта — не более **40 страниц** в пределах домена;
* размер читаемого тела ответа — не более **1 МБ**, для служебных путей — 512 байт;
* принудительная пауза между запросами — не менее **0.5 с**;
* переходы **только в пределах одного домена**, субдомены и внешние ссылки
  исключены (внешние адреса лишь перечисляются в отчёте);
* бюджет запросов распределяется между этапами, чтобы обход не «съел» лимит:
  ~35 % резервируется для проверок конфигурации и активных тестов.

## 7. Безопасность самого сканера

* не отправляет запросы, изменяющие или удаляющие данные; из активных
  проверок используются только GET и отправка форм безопасными значениями;
* формы, похожие на изменяющие состояние (регистрация, оплата, заказ, удаление,
  загрузка файлов, сброс пароля), активно не тестируются — они перечисляются в
  замечаниях. Полностью отключить отправку POST-форм: `--no-post-forms`;
* опасные HTTP-методы только фиксируются по ответу `OPTIONS`, но не вызываются;
* по адресам из `Location` при проверке открытого редиректа переходов не делает;
* не сохраняет значения cookie, токенов и найденных секретов — в отчёт попадают
  только маскированные фрагменты;
* никуда не отправляет результаты: отчёт создаётся локально, сетевые запросы
  идут только на сканируемый домен.

## 9. Проверка работы на локальном стенде

В каталоге `tests/` есть намеренно уязвимое учебное приложение. Оно содержит
типовые ошибки: отсутствуют защитные заголовки, cookie без флагов, дублирующийся
`X-Frame-Options`, `Access-Control-Allow-Origin: *` вместе с
`Allow-Credentials: true`, доступные `/.env` и `/.git/config`, отражённый XSS,
имитация ошибки MySQL, открытый редирект, форма входа по HTTP.

```bash
# Терминал 1 — запустить стенд
python tests/vulnerable_app.py 8099

# Терминал 2 — просканировать его
python scan.py http://127.0.0.1:8099 --max-pages 8 --output report.html
```

Ожидаемый результат: около 80 находок, среди них `High` — доступные `.env` и
`.git/config`, подозрение на XSS и SQL-инъекцию, работа по HTTP.

Автотесты (36 тестов: утилиты, ввод адреса в консоли, лимиты, проверки, база
знаний, диаграмма и экранирование отчёта, полный прогон против стенда):

```bash
python -m unittest discover -s tests -v
```

## 10. Возможные проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| В консоли Windows вместо русского текста «крякозябры» | сканер сам переключает вывод на UTF-8; если проблема осталась, выполните `chcp 65001` или смотрите готовый HTML-отчёт |
| PowerShell ругается на `&` в адресе или обрезает URL | запустите `python scan.py` без аргумента и вставьте полный адрес в ответ на запрос `URL:` (либо возьмите адрес в кавычки) |
| `Целевой адрес недоступен` | неверный адрес, сервер не запущен, закрыт порт или требуется VPN. Проверьте схему: `http://` вместо `https://` |
| Замечание о непройденной проверке сертификата | сертификат самоподписанный или просрочен — это отражено в отчёте как находка. Для тестового контура используйте `--insecure` |
| `Достигнут лимит запросов (200)` | уменьшите `--max-pages`/`--max-depth` либо запустите отдельно `--no-active` и полный прогон |
| Сканирование идёт долго | это ожидаемо: между запросами выдерживается пауза 0.5 с (200 запросов ≈ 2 минуты) |
| Много находок «Безопасно» | это справочные записи; нажмите в диаграмме или в фильтрах уровень «Высокая» либо «Средняя» |
