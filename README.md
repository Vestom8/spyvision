# Spyvision — сканер конфигурации и базовых уязвимостей веб-приложений

**Версия пакета:** `1.1.0` (`webscan`)  
**Интерфейс:** Spyvision (локальный веб-экран + интерактивный HTML-отчёт)  
**Назначение:** образовательный и практический инструмент безопасного анализа веб-приложения в пределах одного домена.

Консольная утилита на Python обходит указанный сайт (до **100** страниц, не более **1000** HTTP-запросов), проверяет настройки безопасности и выполняет **безопасные** активные проверки, затем формирует самодостаточный HTML-отчёт с диаграммой, фильтрами, доказательствами и рекомендациями по исправлению.

Без аргумента URL открывается главный экран **Spyvision** в браузере: ввод адреса и кнопка «Сканировать» запускают проверку и показывают отчёт. Для каждой находки указаны тип угрозы, объяснение опасности простым языком, логика вывода сканера и блок «Как исправить».

Сканер **не выполняет деструктивных действий**, не эксплуатирует уязвимости и не сохраняет пароли и секреты (значения cookie и найденные ключи в отчёте маскируются). При включённом каталожном анализе содержимое страниц, URL и cookie не передаются наружу: в NVD уходят только название/версия компонента или CPE, а KEV и ExploitDB загружаются как справочники и сопоставляются локально.

> ⚠️ Запускайте сканер только против систем, которыми владеете вы, или на тестирование которых у вас есть письменное разрешение. Сканирование чужих сайтов без разрешения может нарушать закон.

## 1. Требования

| Компонент | Требование |
|-----------|------------|
| Python | **3.8** или новее (проверено на 3.8–3.14) |
| ОС | Windows, Linux, macOS |
| Сеть | доступ к сканируемому адресу |
| Зависимости | `requests`, `beautifulsoup4` |
| Стандартная библиотека | `ssl`, `socket`, `urllib.parse`, `http.cookies`, `http.server`, `argparse`, `re`, `difflib`, … |
| Браузер | любой современный (для UI и отчёта) |

## 2.1. Windows-приложение (.exe)

Готовый файл: **`dist\Spyvision.exe`** (один файл, Python на машине не нужен).

### Запуск

1. Откройте `dist\Spyvision.exe` двойным щелчком.
2. Появится окно консоли и браузер с главным экраном Spyvision.

```bat
dist\Spyvision.exe
dist\Spyvision.exe https://example.com --output report.html
dist\Spyvision.exe --cli
```

```bat
build_exe.bat
```

или:

```bash
python -m pip install pyinstaller
python -m PyInstaller --noconfirm --clean Spyvision.spec
```

Спецификация `Spyvision.spec` упаковывает точку входа `scan.py` и ресурс `webscan/landing.html` (нужен для главного экрана внутри exe).

## 3. Запуск и режимы работы

Есть **три** способа указать адрес.

### Способ 1: главный экран Spyvision (рекомендуется)

```bash
python scan.py
```

Сохраняется `index.html`, поднимается локальный HTTP-сервер на `127.0.0.1`, в браузере открывается интерфейс. После скана — переход к `report.html`.

```bash
python scan.py --no-browser          # не открывать браузер автоматически
python scan.py --ui-port 8765        # фиксированный порт
python scan.py --max-pages 10        # лимиты скана действуют и в UI
```

> Главный экран нужно открывать по адресу из консоли (`http://127.0.0.1:…/`), а не как `file://` — иначе кнопка «Сканировать» не сможет вызвать API. Файл `index.html` при этом всё равно пишется на диск.

### Способ 2: URL аргументом

```bash
python scan.py https://example.com --max-pages 20 --max-depth 8 --output report.html
```

### Способ 3: ввод в консоли

```bash
python scan.py --cli
python scan.py --cli --max-pages 10 --output otchet.html
echo https://example.com | python scan.py --cli
```

Пустая строка — повторный запрос URL; `Ctrl+C` — отмена.

### Схема адреса

Если схема не указана (`example.com`, `127.0.0.1:8099`), сканер проверяет TLS на хосте и выбирает `https://`, иначе `http://`. Проверка идёт на уровне TCP/TLS и **не** расходует лимит HTTP-запросов. Выбранная схема печатается в консоль.

### Коды выхода

| Код | Значение |
|-----|----------|
| `0` | успешно |
| `2` | ошибка URL / отмена ввода |
| `3` | не удалось сохранить отчёт |
| `130` | прервано `Ctrl+C` |

## 3.1. Аргументы командной строки

| Аргумент | По умолчанию | Описание |
|----------|--------------|----------|
| `URL` | — (режим UI) | адрес целевого приложения |
| `--cli` | выкл. | спросить URL в консоли вместо веб-интерфейса |
| `--ui-port` | `0` (авто) | порт локального интерфейса |
| `--no-browser` | выкл. | не открывать браузер при старте UI |

| `--output` | `report.html` | путь к файлу отчёта |
| `--max-requests` | `1000` | лимит HTTP-запросов к сайту (жёсткий максимум **1000**; запросы к каталогам уязвимостей не считаются) |
| `--timeout` | `5.0` | таймаут запроса, с (жёсткий максимум **5**) |
| `--delay` | `0.1` | пауза между запросами, с (минимум **0.1**) |
| `--concurrency` | `4` | одновременных запросов при переборе служебных путей и активных проверках (1–8). Частота стартов запросов не растёт (пауза `--delay` сохраняется); при ответах 429/503 сканер сам переходит на 1 запрос и паузу 0.5 с |
| `--no-active` | выкл. | только конфигурация, без активных тестов |
| `--no-vuln-db` | выкл. | отключить NVD/CPE, KEV и ExploitDB |
| `--update-vuln-db` | выкл. | принудительно обновить кэш каталогов; **без URL** — только обновить KEV и ExploitDB и выйти |
| `--vuln-db-cache` | `~/.spyvision/cache` | каталог кэша справочников (или переменная `SPYVISION_CACHE_DIR`) |
| `--vuln-db-ttl-hours` | `24` | срок актуальности кэша, часы |
| `--vuln-db-offline` | выкл. | не обращаться к каталогам по сети — только локальный кэш |
| `--no-exploitdb` | выкл. | не использовать ExploitDB |
| `--max-components` | 30 | сколько компонентов с известной версией сверять с NVD (каждый — 1–3 запроса к NVD) |
| `--max-cves` | 200 | сколько CVE на компонент показывать в отчёте (на время скана не влияет) |
| `--no-post-forms` | выкл. | не отправлять тестовые значения в POST-формы |
| `--insecure` | выкл. | продолжать при недоверенном сертификате (факт всё равно попадает в отчёт) |
| `-v` / `--verbose` | выкл. | печатать каждый HTTP-запрос |

### Примеры

```bash
python scan.py
python scan.py --cli
python scan.py https://example.com
python scan.py https://example.com --max-pages 1 --max-depth 0 --output otchet.html
python scan.py https://example.com --no-active
python scan.py http://127.0.0.1:8000 --max-pages 10 --verbose
python scan.py https://test.local --insecure
NVD_API_KEY=ваш_ключ python scan.py https://example.com --update-vuln-db
python scan.py --update-vuln-db                              # только обновить справочники
python scan.py https://example.com --vuln-db-offline         # без сети к каталогам
```

Переменные окружения: `NVD_API_KEY` (ключ NVD — лимит 50 запросов за 30 с вместо 5),
`SPYVISION_CACHE_DIR` (каталог кэша).

После скана (UI или CLI) сохраняется HTML-отчёт — самодостаточный файл. В режиме UI он также доступен как `/report.html` на локальном сервере.

## 4. Главный экран Spyvision и локальный сервер

### Внешний вид

- бренд **Spyvision**, маскот-паук на нити (цвет паутины `#858585`);
- поле ввода URL и кнопка «Сканировать»;
- подсказки с примерами адресов;
- декоративные паутины в углах.

Исходный макет дизайна: каталог `главный экран сайта/`. Рабочий шаблон для запуска: `webscan/landing.html` (подключается API `/api/scan`).

### Локальный HTTP API (`webscan/ui_server.py`)

Сервер слушает только **`127.0.0.1`** (доступ с других машин по сети не открывается).

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET` | `/`, `/index.html` | главный экран |
| `GET` | `/report.html` (или имя из `--output`) | готовый отчёт |
| `GET` | `/api/status` | `{scanning, report_ready, last_error, last_target, vuln_db}`; `vuln_db` — `{nvd, kev, exploitdb: {state, data_date}}` (до первого скана — состояние локального кэша) |
| `POST` | `/api/scan` | тело JSON `{ "url": "…" }` → сканирование → `{ok, report_url, target}` |

Типичные коды ответов API: `400` (плохой URL/JSON), `409` (скан уже идёт), `500` (ошибка скана), `404` (отчёт ещё не готов).

Поток в браузере: `fetch("/api/scan")` → при успехе `location.href = report_url`.

Артефакты на диске в каталоге запуска: `index.html`, `report.html`.

## 5. Пайплайн сканирования

Оркестрация: `webscan.scanner.run_scan` → результат `ScanResult` (находки + статистика).

Бюджет запросов к сайту распределяется между этапами: **30 %** резервируется после обхода; при активных проверках ещё **18 %** — под проверки уровня сайта, чтобы обход не «съел» весь лимит. Этап 6 не расходует этот бюджет: к сайту он не обращается вовсе.

1. BFS-обход сайта → страницы, формы и ссылки.
2. Пассивные проверки → заголовки, cookies, формы, JS, SAST и утечки.
3. Проверки уровня сайта → TLS, CORS, методы и служебные пути.
4. Broken Access Control → административные пути, IDOR и обход 403.
5. Безопасный DAST → XSS, SQLi, redirect, SSTI, LFI, cmd и CRLF.
6. Каталожная корреляция → fingerprint, CPE/NVD, приоритет KEV и контекст ExploitDB.

После этапов формируется единый HTML-отчёт (`build_report`).

### Этап 1 — обход (`webscan/crawler.py`)

- очередь BFS в пределах **одного хоста** (`same_host`);
- лимиты: `max_pages`, `max_depth`;
- извлечение ссылок и форм (BeautifulSoup);
- внешние ссылки **не** обходятся (могут быть перечислены в отчёте);
- если не загружена ни одна страница — находка `target_unreachable` (High).

### Этап 2 — на каждой странице

Модули: `headers`, `cookies`, `tls` (mixed content), `forms`, `infoleak`, `clientside`, `exposed` (directory listing).

### Этап 3 — уровень сайта

Модули: `tls` (HTTPS/сертификат), `cors` (+ preflight), `methods` (только `OPTIONS`), `exposed` (типовые пути + `robots.txt`).

### Этап 4 — активные проверки (`checks/active.py`)

Точки входа: URL-параметры и поля форм (с ограничениями на число параметров и пропуском «опасных» форм). Маркеры тестовых строк содержат префикс **BAUMAN_***, чтобы их было легко узнать в логах и ответах.

User-Agent HTTP-клиента: `BaumanSecScanner/1.0 (educational configuration scanner; …)`.

### Этап 6 — известные уязвимости (`fingerprint.py`, `vulndb/`)

| Роль | Источник | Что даёт |
|---|---|---|
| Ядро | **NVD API 2.0** | CPE, список CVE, CVSS (v4.0 → v3.1 → v3.0 → v2, приоритет `Primary`), CWE, диапазоны версий |
| Приоритизация | **CISA KEV** | «реально эксплуатируется», дата добавления, срок (`dueDate`), `requiredAction`, использование шифровальщиками |
| Контекст эксплуатации | **ExploitDB** | наличие публичного эксплойта, тип, платформа, verified, ссылка |

1. **Fingerprint** (`fingerprint.py`) — только по уже полученным ответам, **ни одного запроса к цели**: заголовки `Server`, `X-Powered-By`, `X-AspNet-Version`, `X-Generator`, `<meta name="generator">`, имена и баннеры JS/CSS (`jquery-3.4.1.min.js`, `/*! jQuery v3.4.1`), CDN-пути, `/wp-content/`, имена cookie (`PHPSESSID`, `JSESSIONID`, `laravel_session` — продукт без версии). Сигнатуры описаны данными (`SIGNATURES`), пары `vendor:product` сверены со словарём NVD CPE (у nginx две: `f5:nginx` и `nginx:nginx`). Компонент без версии в NVD не отправляется — в отчёте он помечен «версия скрыта (это хорошо)».
2. **NVD** (`vulndb/nvd.py`) — `cpeMatchString` для диагностики точной CPE; CVE запрашиваются по `virtualMatchString=cpe:2.3:a:{vendor}:{product}:*` с пагинацией, затем версия **локально** сверяется с `configurations[].nodes[].cpeMatch[]` (`versionStart/End Including/Excluding`) через `vulndb/versions.py`. Совпадение: «точная версия», «в диапазоне» или «только продукт». Лимит NVD соблюдается скользящим окном (5 или 50 запросов за 30 с); на 403/429/5xx — до 3 попыток с экспоненциальным backoff и учётом `Retry-After`. Проверяется до 15 компонентов, в отчёт — до 50 CVE на компонент (остальное — «и ещё K»).
3. **CISA KEV** и **ExploitDB** скачиваются целиком и сопоставляются по CVE локально. KEV и ExploitDB обновляются с `ETag`/`If-Modified-Since`.
4. **Приоритет и находки** (`vulndb/scoring.py`) — одна находка на компонент со списком CVE внутри; `kind` = `known_cve_kev` (есть CVE из KEV), `known_cve` или `component_version_disclosed` (версии раскрыты, CVE не найдено). Точность всегда **«подозрение»**: версия из баннера может быть бэкпортирована дистрибутивом. Формула приоритета — в разделе 8.
5. Если по той же библиотеке есть CVE из каталогов, эвристическая находка «Устаревшая клиентская библиотека» из `checks/clientside.py` скрывается, чтобы не дублировать запись.

**Кэш** (`vulndb/cache.py`): `~/.spyvision/cache`, рядом с каждым файлом `*.meta.json` (`fetched_at`, `etag`, `last_modified`, `sha256`, `source_url`, `data_date`), атомарная запись и lock-файл (UI и CLI не качают одно и то же одновременно). Стратегия: свежий кэш → используется; устарел → попытка обновить, при ошибке — старые данные с пометкой «данные от ДД.ММ.ГГГГ»; нет ни кэша, ни сети → источник «недоступен», скан продолжается. Если компонентов с версией нет, каталоги вообще не запрашиваются.

## 6. Что проверяется

### 6.1. Проверки конфигурации

| Группа | Что проверяется |
|--------|-----------------|
| Защитные заголовки | `Content-Security-Policy`, `Strict-Transport-Security`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`; устаревший `X-XSS-Protection`; CORS в ответе страницы; небезопасные директивы CSP (`unsafe-inline`, `unsafe-eval`); малый `max-age` у HSTS; дубли и конфликты заголовков |
| HTTPS и TLS | использование HTTPS; редирект HTTP→HTTPS (и его тип); валидность сертификата, срок, домен; устаревший TLS; смешанный контент (активный и пассивный) |
| Cookies | `Secure`, `HttpOnly`, `SameSite` (`Strict`/`Lax` ок, `None` — предупреждение); срок жизни **> 30 дней** |
| CORS | сторонний `Origin`, `null`, `*`; отражение Origin; `*` + `Credentials: true`; preflight `OPTIONS` |
| Служебные ресурсы | **27** типовых путей (`.env`, `.git/config`, бэкапы, swagger, phpinfo, actuator, ключи AWS и т. д.). Читаются статус и первые **512** байт; «мягкие 404» отсекаются эталонным запросом к несуществующему пути |
| HTTP-методы | только `OPTIONS` → анализ `Allow` / `Access-Control-Allow-Methods` на `TRACE`, `TRACK`, `PUT`, `DELETE`, `CONNECT`, `PATCH`. Сами методы **не вызываются** |
| Листинг и `robots.txt` | признаки автоиндекса; служебные разделы из `robots.txt` |
| Клиентская часть | SRI (`integrity`), `target="_blank"` без `noopener`, устаревшие библиотеки, кэш приватных страниц, секреты в URL, iframe без `sandbox`, email в коде, upload-формы, inline-обработчики |
| Опасные места в JS | DOM XSS (`location`/`referrer`/`name` → `innerHTML`/`write`/`eval`); `postMessage` без проверки `origin`; токены в `localStorage`; `ws://` с HTTPS-страницы |

### 6.2. Активные проверки (безопасные)

| Проверка | Как выполняется |
|----------|-----------------|
| Отражённый XSS | маркер `BAUMAN_TEST_92841"'><x-BAUMAN_TEST_92841>` в параметры и поля форм. Без HTML-экранирования — подозрение с контекстом (текст / атрибут / `<script>`). Нагрузка **без** обработчиков событий — не исполняется в браузере |
| SQL-инъекция | `'`, `"`, `\`; сравнение статуса, сообщений СУБД (MySQL, PostgreSQL, SQLite, Oracle, MS SQL, ORM) и структуры HTML. Только «подозрение», без эксплуатации |
| NoSQL | те же спецсимволы; маркеры MongoDB / Elasticsearch / Redis в ответе |
| SSTI | выражение `7*191` в синтаксисах популярных шаблонизаторов; находка, если рядом с меткой есть вычисленный результат |
| Чтение файлов (LFI) | пути с `..` к `/etc/passwd` или `windows\win.ini` — только чтение |
| Команды ОС | после `;` имя несуществующей команды; признак — сообщение shell. Реальные команды не выполняются |
| CRLF | `%0d%0a` + пробный заголовок; признак — появление заголовка в ответе |
| Открытый редирект | параметры `url`/`redirect`/`next`/… → `https://evil.com`; проверка `Location` и `meta refresh` **без перехода** |
| Небезопасные формы | HTTP, пароль по HTTP, GET+sensitive, нет CSRF-токена, внешний `action` |
| Утечки информации | `Server` / `X-Powered-By` / generator, пути ФС, внутренние IP, комментарии, `.map`, стек, похожие на секреты строки (маскируются) |

Дорогие активные тесты (SSTI, LFI, cmd, CRLF) ограничены числом первых точек входа, чтобы уложиться в бюджет запросов.

## 7. Модель находок

Класс `Finding` (`webscan/models.py`).

### Уровень критичности (`severity`)

| Код | В UI / диаграмме | Смысл |
|-----|------------------|--------|
| `HIGH` | Высокая | прямая угроза данным/аккаунтам |
| `MEDIUM` | Средняя | защита ослаблена, есть сценарий атаки |
| `LOW` | Низкая | гигиена конфигурации, помощь разведке |
| `INFO` | **Безопасно** | проблем нет или запись справочная |

### Категория

- **Конфигурация** — настройки сервера и приложения;
- **Уязвимость** — признаки ошибок обработки ввода / логики.

### Точность (`confidence`)

- **подтверждено** — факт прямо в ответе (нет заголовка, файл отдаётся 200 с ожидаемым содержимым);
- **подозрение** — нужен ручной разбор (например, отражение без экранирования).

### Автозаполнение текстов

При создании находки по полю `kind` подтягиваются:

- из `webscan/knowledge.py` — тип угрозы, «чем опасно», «почему сканер так решил»;
- из `webscan/fixes.py` — развёрнутый текст «как исправить» (если есть).

Дедупликация в списке: ключ `(url, title, request)`.

## 8. Как читать HTML-отчёт

Генератор: `webscan/report.py` → один HTML-файл со встроенными CSS и JS.

### Главный экран отчёта

1. Кнопка **«Выйти на главный экран»** (слева сверху) → `index.html`.
2. Под ней — декоративный паук на статичной паутине `#858585` (паук слегка покачивается).
3. **Справа сверху** — угловая паутина.
4. **Слева** — кольцевая диаграмма «Статистика уязвимостей» (уровни кликабельны = фильтр таблицы); кнопка-меню (три полоски) слева от карточки диаграммы открывает боковую панель.
5. Под диаграммой — **«Скачать PDF»** (сводка высокого уровня через печать браузера) и сводка длительности / числа проверок.
6. **Справа** — бренд, заголовок, цель, время формирования, блок **«Общая статистика»** из трёх групп:
   - *Найденные проблемы* — в т. ч. подтверждённые угрозы высокого уровня, требуют внимания, уязвимости, конфигурация;
   - *Что просканировано* — страницы, формы, параметры, протокол;
   - *Как выполнялось* — запросы, проверки, активные тесты, запросы без ответа.
7. Внизу — дисклеймер о безопасных проверках и тестовых маркерах.

Карточки статистики (кроме чисто справочных) кликабельны: открывают таблицу с фильтром или раздел боковой панели.

### Боковая панель (drawer)

- Найденные проблемы (таблица + фильтры);
- Как читать отчёт;
- Просканированные страницы;
- Какие проверки выполнялись;
- Известные уязвимости компонентов (если этап 6 включён);
- Запросы без ответа.

### Таблица находок

- фильтры: **уровень**, **категория**, **точность** (Подтверждено / Подозрение), **поиск**;
- кнопки **«PDF по фильтру»**, **«Развернуть все»**, **«Сбросить»**;
- одинаковые названия группируются со счётчиком; раскрытие показывает экземпляры (URL, доказательства);
- у каждой записи: чем опасно, почему так решил сканер, запрос, ответ, **как исправить** (краткое пояснение + кнопка **«подробнее»**);
- подтверждённые High визуально выделены.

### PDF

- **«Скачать PDF»** — печать блока со всеми High (сначала подтверждённые);
- **«PDF по фильтру»** — только видимые после фильтров строки таблицы.

В режиме печати браузера скрывается интерактивная оболочка, остаётся печатная вёрстка.

### Известные уязвимости компонентов

- В «Общей статистике» — группа карточек: *компонентов определено*, *CVE найдено*, *из них в CISA KEV*, *с публичным эксплойтом*; щелчок открывает раздел с соответствующим фильтром.
- **Состояние справочников**: для NVD, KEV и ExploitDB — «свежий / обновлён / устаревший (данные от …) / недоступен / не запрашивался», дата данных, число записей и запросов.
- **Таблица CVE**: компонент и версия (с типом совпадения), где найден, CVE (ссылка на NVD, CWE, дата публикации, описание во всплывающей подсказке), CVSS (вектор в подсказке, бейдж «Критическая (CVSS 9.8)» при ≥ 9.0), KEV (бейдж, срок, шифровальщики), ExploitDB (число и ссылки, ✓ — verified), приоритет.
- **Фильтры**: «только CISA KEV», «есть публичный эксплойт», диапазон CVSS; «PDF по фильтру».
- **«Выгрузить для аудита (CSV)»** — файл собирается в браузере из встроенного JSON: `CVE; Компонент; Версия; CVSS; Рекомендация; В KEV; Публичный эксплойт` (UTF-8 с BOM и разделителем «;» — Excel открывает кириллицу без настройки; значения, начинающиеся с `=`, `+`, `-`, `@`, нейтрализуются от CSV-инъекции).
- Печатная сводка «Скачать PDF» дополнительно содержит CVE из KEV и критические (CVSS ≥ 9).

**Формула приоритета CVE** (константы — в `webscan/vulndb/scoring.py`):

| Фактор | Эффект |
|---|---|
| CVSS base score | база 0–10  |
| CVE в CISA KEV | **+3**, метка «Эксплуатируется», уровень находки не ниже High |
| KEV + `knownRansomwareCampaignUse = Known` | ещё **+1** |
| Verified-эксплойт в ExploitDB | **+1.5** (непроверенный — **+0.75**) |
| Совпадение «только продукт» | **×0.5** |

Уровень находки по компоненту — максимальный по его CVE: KEV или CVSS ≥ 7.0 → High; 4.0–6.9 → Medium; ниже → Low. Отдельного уровня Critical нет — вместо него бейдж.

Все строки из внешних каталогов (описания CVE, названия эксплойтов) выводятся с HTML-экранированием, а встроенный JSON экранирует `</` — XSS через каталог в собственном отчёте невозможен. Отчёт остаётся самодостаточным: без внешних скриптов и стилей.

### Рекомендации по приоритету

| Уровень | Что делать |
|---------|------------|
| **High** | разбирать в первую очередь (секреты, XSS/SQLi-подозрения, пароль по HTTP, …) |
| **Medium** | планировать исправление (нет CSP/HSTS/XFO, открытый редирект, cookie без флагов, …) |
| **Low** | по возможности (XCTO, долгие cookie, `.map`, inline-обработчики, …) |
| **Info / Безопасно** | к сведению |

Раздел замечаний предупреждает о неполном скане: лимит страниц/запросов, пропуск форм, обрезка тела 1 МБ, проблемы сертификата.

**Важно:** пустой отчёт **не** доказывает отсутствие уязвимостей. Сканер — ограниченный безопасный набор проверок, не замена ручному аудиту и пентесту.

## 9. Ограничения выполнения

Заданы жёстко в `webscan/http_client.py` и не могут быть превышены флагами CLI:

| Параметр | Значение |
|----------|----------|
| Таймаут запроса | ≤ **5** с |
| HTTP-запросы к сайту | ≤ **1000** (редиректы в истории тоже считаются; запросы к каталогам — отдельно) |
| Страниц обхода | ≤ **100** |
| Тело ответа | ≤ **1 МБ** (служебные пути — peek **512** байт) |
| Пауза между запросами | ≥ **0.1** с |
| Домен | только исходный хост; субдомены и внешние ссылки не обходятся |
| Редиректы клиента | до 5 за запрос |

Ориентир по времени: при полном бюджете 1000 запросов и паузе 0.1 с — порядка **2–5 минут** плюс время ответов сервера. Первый скан с каталогами дольше: загрузка ExploitDB (~10 МБ) и ответов NVD; без `NVD_API_KEY` NVD допускает 5 запросов за 30 с. Повторные сканы берут данные из кэша.

## 10. Безопасность самого сканера

- не удаляет и не изменяет данные деструктивно; из активных проверок — GET и безопасная отправка форм тестовыми маркерами;
- формы, похожие на регистрацию / оплату / удаление / upload / сброс пароля, активно не тестируются (перечисляются в замечаниях); полный запрет POST: `--no-post-forms`;
- опасные HTTP-методы только читаются из ответа `OPTIONS`, не вызываются;
- по `Location` при проверке редиректа **не переходит**;
- cookie, токены и секреты в отчёте **маскируются**;
- **что уходит наружу при каталожном анализе**: в NVD — только строки CPE (`cpe:2.3:a:vendor:product[:version]`), название продукта для `keywordSearch` и параметры пагинации. URL цели, cookie, заголовки и содержимое страниц **не передаются** (это проверяет автотест). KEV и ExploitDB скачиваются целиком и сопоставляются локально;
- к каталогам ходит отдельный HTTP-клиент: только HTTPS и только хосты `services.nvd.nist.gov`, `www.cisa.gov`, `raw.githubusercontent.com` (зеркало KEV), `gitlab.com` (ExploitDB); проверка TLS не отключается никогда;
- эксплойты **не скачиваются и не запускаются** — в отчёт попадают только метаданные и ссылка;
- ошибка любого каталога не прерывает скан: в отчёте появляется замечание, используется устаревший кэш;

## 14. Проверка на учебном стенде и автотесты

В `tests/vulnerable_app.py` — намеренно уязвимое учебное приложение: нет защитных заголовков, cookie без флагов, CORS `*` + credentials, открытые `/.env` и `/.git/config`, отражённый XSS, имитация ошибки MySQL, открытый редирект, форма входа по HTTP.

```bash
# Терминал 1 — стенд
python tests/vulnerable_app.py 8099

# Терминал 2 — скан
python scan.py http://127.0.0.1:8099 --max-pages 8 --output report.html
```

Ожидается порядка **~80** находок; среди High — `.env`, `.git`, подозрения на XSS/SQLi, работа по HTTP.

Автотесты:

```bash
python -m unittest discover -s tests -v
# или
python tests/test_scanner.py
```

Покрывают утилиты, ввод URL, лендинг/UI-хелперы, лимиты, отдельные checks, отчёт, базу знаний, `FindingList`, end-to-end против стенда. `test_vulndb.py` проверяет этап 6 полностью без сети (транспорт подменяется, данные — из `tests/fixtures/vulndb/`): сравнение версий, fingerprint, кэш и stale-fallback, 429 → повтор, офлайн-режим без запросов, отсутствие данных цели в запросах к NVD, цепочку Apache 2.4.49 → CVE-2021-41773 → KEV + ExploitDB → High, экранирование XSS из описаний CVE и CSV-экспорт (через Node.js, если установлен).

Вспомогательно:

```bash
python tests/inspect_report.py report.html
python tests/expand_details.py report.html expanded.html
```

## 16. Возможные проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| В консоли Windows «крякозябры» | сканер переключает вывод на UTF-8; иначе `chcp 65001` или смотрите HTML-отчёт |
| PowerShell ломает URL с `&` | `python scan.py` (UI) или `--cli`, либо URL в кавычках |
| «Целевой адрес недоступен» | неверный адрес, сервер не запущен, порт/VPN; попробуйте `http://` вместо `https://` |
| Замечание о сертификате | самоподписанный/просроченный — это находка; для тестового контура `--insecure` |
| «Достигнут лимит запросов (1000)» | уменьшите `--max-pages` / `--max-depth` или сначала `--no-active` |
| Долгое сканирование | пауза 0.1 с между запросами; для ускорения: `--no-active`, ключ `NVD_API_KEY` (лимит NVD 5 → 50 запросов за 30 с), `--concurrency` |
| Много записей «Безопасно» | справочные; в диаграмме/фильтрах выберите «Высокая» / «Средняя» |
| UI не сканирует с `file://` | откройте URL из консоли `http://127.0.0.1:…/` |
| После правок кода UI «старый» | перезапустите `python scan.py` — модули загружаются при старте процесса |
| В exe нет главного экрана | пересоберите с актуальным `Spyvision.spec` (должен включать `landing.html`) |
| В отчёте 0 CVE | чаще всего сайт не раскрывает версии (это хорошо) — см. «Распознанные компоненты»; либо компонента нет в сигнатурах `fingerprint.py`; либо NVD/каталоги недоступны — см. «Состояние справочников» |
| NVD: 403 / 429 | превышен лимит NVD (5 запросов за 30 с без ключа). Сканер ждёт и повторяет до 3 раз; получите бесплатный ключ на nvd.nist.gov и задайте `NVD_API_KEY` |
| Каталоги недоступны, нужна повторяемость | `--vuln-db-offline` — только локальный кэш, ни одного сетевого запроса к каталогам |

## 17. Глоссарий

| Термин | Значение в проекте |
|--------|--------------------|
| **Spyvision** | бренд UI главного экрана и отчёта |
| **BaumanSecScanner** | идентификатор в User-Agent (образовательный сканер) |
| **kind** | машинный ключ вида находки в базе знаний |
| **подтверждено / подозрение** | степень уверенности |
| **Конфигурация / Уязвимость** | категория |
| **High / Medium / Low / Info** | уровни; Info в диаграмме подписан «Безопасно» |
| **активные проверки** | подстановка тестовых значений в параметры/формы без эксплуатации |
| **мягкий 404** | сервер отвечает 200 на несуществующий путь — отсекается эталоном |
| **SRI** | Subresource Integrity — атрибут `integrity` у внешних скриптов/стилей |
| **CSP / HSTS / XFO** | заголовки Content-Security-Policy, Strict-Transport-Security, X-Frame-Options |
